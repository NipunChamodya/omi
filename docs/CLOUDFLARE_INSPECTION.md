# Remote-testing inspection — before infrastructure changes

Inspected on branch `dev`; the initial worktree was clean. All ten requested documents exist and were read. Previous reports describe historical stages; current source is the authority for configuration below.

- Frontend: `npm run build` produces `apps/web/dist`. Vite listens on 127.0.0.1:5173 with strict port handling. Only `/api` is proxied, to 127.0.0.1:3000 by default, stripping `/api` and supporting upgrades.
- Backend: `apps/server/src/index.ts` loads dotenv from its working directory, parses configuration and starts Fastify. Defaults HOST=127.0.0.1, PORT=3000. No reverse-proxy trust was configured initially; rate limits use request.ip, which would group tunneled players under the proxy's address.
- Browser API: VITE_API_URL defaults to `/api`; all HTTP requests are credentialed. Socket URL is `${apiBase}/rooms/:roomId/ws`, constructed against the browser origin and converted to ws/wss from its scheme. No separate socket host is required.
- API routes (backend paths): GET `/health`; POST `/transport/session`, `/rooms`, `/rooms/preview`, `/rooms/snapshot`, `/rooms/join`; GET `/rooms/:code/preview`, `/rooms/:roomId/snapshot`, `/rooms/:roomId/ws`; POST `/auth/session`, `/auth/google/start`, `/auth/logout`, `/profile`, `/profile/avatar`, `/profile/avatar/remove`; GET `/auth/google/callback`, `/avatars/:id/:size`; multiplayer OPTIONS catchall. NGINX must strip `/api/` to preserve these paths.
- Google: GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET and GOOGLE_CALLBACK_URL are all-or-none. Existing server .env has all three configured; values were not printed. Guests are false. The production issuer is fixed to Google. Test identity providers exist only in explicit fixtures and cannot be selected through environment configuration.
- Public callback through the verified prefix is `/api/auth/google/callback`. Callback construction uses configured URL, not Host/forwarded headers. PKCE, state, nonce and signed ID tokens are required.
- Production account cookies: Secure, HttpOnly, SameSite=Lax, Path=/, host-only __Host names. Sessions last seven days and are stored by credential hash. Login rotates credentials; logout revokes the session and closes its socket. Account mutations require exact Origin plus CSRF. Multiplayer HTTP and socket upgrades require exact Origin and membership. Callback and public avatar GET routes have narrowly defined Origin exemptions.
- CSP: the frontend Vite security plugin injects one meta policy; development nonces and loopback sockets are absent from production builds. An exact HTTPS VITE_API_URL adds exact HTTPS/WSS origins. NGINX must not add a conflicting full CSP. Frame-ancestors requires its own HTTP directive.
- Database: DATABASE_PATH defaults to `./data/omi.sqlite` relative to the server workspace. Drizzle migrations are applied through the existing runner/startup. File mode 0600, WAL and foreign keys are enabled. Never move or reset an existing database. Rooms/scores/action receipts are in-memory only.
- Limits: 100 rooms, 1,000 transport sessions/cache entries, 64 queued actions/room, 512 retained action receipts/member, 120 HTTP requests/minute/IP, 60 messages/10 seconds/identity, 4 KiB socket frames, 64 KiB outgoing buffer cap and 30-second maintenance/heartbeats. Uploads have a 4 MiB file cap, two active pipelines and six/minute/account; image decoding has separate pixel/time bounds. API body cap is 16 KiB except explicit multipart handling.
- No NGINX or cloudflared executable was installed. Homebrew is `/opt/homebrew`; no default ~/.cloudflared/config.yml or config.yaml was found. Installation will use Homebrew without modifying its global NGINX configuration or starting a global service.

Decision: use one independent loopback NGINX process serving only copied production build files, exact same-origin `/api` proxying, a production-mode backend with guests disabled, and a Quick Tunnel initially pointing to a maintenance-only gate. The generated hostname must be registered/accepted by Google before an explicit activation command exposes the application. Never publish the fixture provider or substitute guest authentication. Missing Google/domain approval blocks public gameplay, not local infrastructure development.
