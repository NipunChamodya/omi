# Stage J — Security review

Reviewed on 2026-10-27 against the repository on `dev`. This is an implementation review and regression assessment, not an independent penetration test or production certification. No external target was attacked. Tests and fixtures remain loopback-only.

## Findings and disposition

| Finding                                               | Evidence                                                                                              | Disposition                                                                                                                                                                                                                                      |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Outdated runtime                                      | Installed Node was 22.13.1; official Node 22.23.4 is a newer security release                         | `.nvmrc`/package minimum, production startup and readiness gate require 22.23.4+ within Node 22. Official archive SHA-256 verified and patched runtime used for final checks. Global Node untouched; real service must activate patched runtime. |
| Local credential-file exposure                        | Metadata-only inspection found `apps/server/.env` mode 0644                                           | Tightened to 0600 without reading, printing or changing its contents. Readiness checks a present file's type/mode. Historical credential revocation remains owner-controlled.                                                                    |
| Query values in plugin path logging                   | Installed WebSocket plugin logs `rawRequest.url` under `path` on unsupported upgrades                 | Shared logger path serializer removes query/fragment and bounds length; compiled real-upgrade test confirms synthetic query markers are absent. Existing request serialization and cookie redaction remain.                                      |
| Missing API response security defaults                | Backend headers previously depended mostly on child routes/proxy                                      | Added no-store/nosniff/no-referrer and a data-only CSP; production HSTS only. Frontend policy remains separate and browser render checks prove it is not replaced by API CSP.                                                                    |
| Endpoint URL credentials/unsupported schemes accepted | Existing config accepted userinfo in callback/storage and non-HTTP loopback storage URLs              | Reject credential-bearing callback/storage URLs; storage permits HTTPS or explicit non-production loopback HTTP. Regression tests cover rejection.                                                                                               |
| Operational assurance missing                         | No verified backup/restore CLI, runtime health aggregation, patched-runtime gate or real load harness | Added read-only/WAL-aware backup, new-file restore with session invalidation, aggregate monitoring, readiness, bounded shutdown, static bundle checks and private load testing. External recovery/monitoring remains pending.                    |

## Dependencies and runtime

Both `npm audit --omit=dev --json` and `npm audit --json` returned zero reported vulnerabilities on the review date. This is an advisory snapshot, not proof of absence of vulnerabilities and not a runtime scan. The Node issue was identified separately using the official [Node 22.23.4 security release](https://nodejs.org/en/blog/release/v22.23.4) and [October security bulletin](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases). Recheck advisory/runtime updates before public deployment. No npm dependency version upgrade or unrelated package refactor was required; the lockfile runtime engine declaration changed only.

## Remaining release risks

The actual development environment fails production readiness for mode/proxy, secure-origin-or-guests, avatar storage, TURN and absolute database path. Public Google redirect registration and historical credential revocation require owner/external-account action. Physical devices, installed app sessions, remote connectivity, public TURN/NAT, host sleep/restart, S3 recovery and external monitoring remain open. Existing game-rule uncertainties still gate ordinary next rounds/accusation/no-trump workflows; no rule was invented or automatic cheating warning/penalty added.

The review follows the relevant [OWASP WebSocket guidance](https://cheatsheetseries.owasp.org/cheatsheets/WebSocket_Security_Cheat_Sheet.html) on Origin/session authorization, resource limits and safe logging. Shutdown/header behavior uses the installed Fastify/WebSocket implementation and [Fastify lifecycle documentation](https://fastify.dev/docs/latest/Reference/Hooks/); backup design uses the [SQLite online backup API](https://sqlite.org/backup.html). See OPERATIONS.md and STAGE_J_REPORT.md for executed evidence and release gates.
